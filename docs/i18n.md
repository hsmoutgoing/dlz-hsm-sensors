# Six-language rendering

Locales: en, zh, es, de, fr, ja. English is the default and dictionary keys are English source strings. Non-English dictionaries are flat JSON objects in src/lib/i18n/messages. Blank/missing entries fall back to English; matching also normalizes whitespace.

POST /api/locale accepts {locale}, validates the allowlist and writes the HttpOnly hsm-locale cookie (one year, SameSite=Lax). The header selector reloads the current URL after writing the cookie. No URL/slug migration and no DOM replacement is involved. Root layout and server pages use request-scoped React cache and asynchronous cookies(); Client Components get the exact same locale/dictionary through I18nProvider, including their server-rendered HTML.

Server Components: getI18n() for async functions; useTranslations() for synchronous components (React use on the cached request promise). Client Components: useTranslations() from lib/i18n/client. Use tx(value) only at display boundaries, never when creating API payloads, hrefs, keys, filters, IDs or form state. Product/category content stays canonical English and is translated at display time. Do not translate model codes, numeric specifications, user input or inquiry records.

Static page metadata uses localizeMetadata; product/category metadata explicitly translates source fields. JSON-LD deliberately stays canonical English. Cookie-based locale has no separate localized URLs/hreflang; SEO localized URL routing is future work.

The one-shot scripts/integrate-i18n.cjs used the TypeScript AST to integrate existing JSX. Do NOT rerun on already transformed sources (not idempotent). Review new text manually, especially dynamic template literals, accessible attributes and strings assembled from fragments. Translation completeness depends on dictionary coverage and editorial review; architecture alone does not imply full translation coverage.
